# 规则全文

## 格式

```
type(scope): 中文说明

为什么这么做，有什么约束或取舍。

- 关键改动点
- 边界条件

Refs: TMDBP-040
Verified: npm test -- cache
Co-authored-by: pi <noreply@pi.local>
```

## type 白名单

| type | 用在 | 不要用在 |
|---|---|---|
| `feat` | 新增用户可见能力 | 只是导入既有代码却写「增强功能」 |
| `fix` | 修正错误行为 | 改措辞、调样式 |
| `perf` | 快或省 | 只记了测量结论（那是 `docs`） |
| `refactor` | 行为不变的结构调整 | 顺带改了行为 |
| `docs` | 文档、注释、README、结论存档 | 代码 |
| `test` | 只动测试 | 带生产代码的改动 |
| `build` | 依赖、镜像、工具链 | 业务逻辑 |
| `ci` | 流水线配置 | 构建脚本 |
| `chore` | 杂项、版本号、`chore(auto):` | 任何改变行为的事 |
| `style` | 格式、空白、排版 | 逻辑 |
| `revert` | 回滚 | — |

## scope

必填，小写英文，允许 `-` `_` `.` `/`。来源优先级：

1. 顶层目录名（`proxy` `console` `dashboard`）
2. 领域词（`auth` `cache` `search` `upload`）
3. 平台标记（`windows` `arm64` `release` `deps`）

反例：`fix(监控):`、`fix(修复):`、`feat():`。

### 界面类改动没有 `ui` 类型

`ui` 不是 type。按改动性质归到已有类型，scope 才用 `ui` 或模块名：

| 改动 | 写法 |
|---|---|
| 只改样式、布局、间距、配色 | `style(catalog): 优化首页筛选结果头` |
| 界面行为变了（交互、状态、跳转） | `fix(player): 换季后选集跟随当前季` / `feat(...)` |
| 组件重构、行为不变 | `refactor(ui): 拆分 Diagnostics surface` |

## 长度

- 标题 ≤ 50 字符（中文按字，不是按字节）。上限不是目标，30 上下最好读。
- 超过时把枚举、文件名清单、并列项移进正文。
- 正文每行不限，但单行超过 100 字符要换行。

## 拆与不拆

出现下列任一情况必须拆成多条提交：

- 标题里出现「和 / 并 / 以及 / 同时 / and」
- 改动可以独立回滚（升级依赖 + 改逻辑）
- 一类是 `build`/`ci`，另一类是 `feat`/`fix`
- 一条提交里有多个 `scope`

不拆的情况：改一个行为连带改它的测试、类型、文档，属于同一件事。

## 正文何时强制

| 情况 | 正文 |
|---|---|
| 行为 / 接口 / 配置默认值变化 | 必须 |
| 单条改动 > 100 行 | 必须 |
| 删除功能或文件 | 必须，写清为什么不需要了 |
| 跨模块 | 必须，写清各模块的关系 |
| 纯格式、纯文档、纯版本号 | 可省 |

## Trailer

```
Refs: <ID>              有工单或 issue 时必填；消息里出现 [ABC-123] / #123 也要补
Verified: <命令>         真跑过命令时必填，写命令本身，不写「已测试」
Co-authored-by: <名字>   agent 参与时署名
```

破坏性变更用 `feat(scope)!: 说明` 并在正文首行写 `BREAKING CHANGE: 影响面与迁移方式`。

## 机器与记账提交

| 类型 | 处理 |
|---|---|
| 定时任务刷时间戳（如证书到期表） | `chore(auto): <做了什么>`，且不进主分支，或加 `[skip ci]` |
| agent 的 journal / archive 记账 | 不提交，加进 `.gitignore`；确需留档放独立 `journal` 分支 |
| 批量格式化 | 单独一条 `style:`，不与业务改动混在一起 |
| 版本号推进 | `chore(release): 0.2.131+137` |

## 合并

- 默认 squash：PR 标题即最终 commit 标题，正文放 PR 描述
- 保留 merge commit 时，消息里必须写清合并了什么，不能只留分支名
- `git commit --no-verify` 不得用于绕过本文规则
