# ADR 规则全文

## 1. 先适配目标项目，再套默认约定

在已有仓库起草 ADR 之前，依次检查：

1. 仓库根目录的 `AGENTS.md`（或 `docs/README.md`）是否规定了 ADR 路径、语言或联动文档；
2. 目标 ADR 目录中最近的 2–3 篇文档，确认编号宽度（默认 4 位 `0001`）、状态词写法（中文「已接受」或英文 `Accepted`）与常用章节名。

原则：**项目已有成熟习惯优先于本文件默认值**；新建 ADR 目录时直接采用本文件默认值。

## 2. 准入与排除细则

### 必须或应当写 ADR

- **边界变化**：服务拆分或合并、进程职责重新划分、存储选型、主真相源变更。
- **外部协议与通道切换**：认证方式、第三方接口切换、缓存/同步一致性模型变更。
- **推翻既有决定**：旧 ADR 或既定架构约束不再成立，需要明确废止范围。
- **高争议取舍**：多个合理方案之间做选择，若不留理由，半年后人或 Agent 很可能把旧方案改回来。
- **跨步大重构**：无法在单次提交内完成、必须按顺序逐块迁移的结构改造（用「重构拆步型」ADR 定蓝图与收尾判据）。

### 不应写 ADR

- 单次 Bug 修复（原因与验证进 commit message 和回归测试）。
- 局部功能增改，未触及公共边界或长期约束。
- 样式调整、文案润色、普通依赖版本升级。
- 过程态信息：当天的调试日志、未定稿的脑暴草稿、本机环境待办、带日期的交接流水账。

判断口诀：**三个月后有人问「当初为什么这么定、为什么不选 B」，需要这份记录回答吗？** 需要就写；只是回答「今天做到第几步」，就不该写进 ADR。

## 3. 文件命名与编号

- 目录默认 `docs/adr/`。
- 文件名：`NNNN-<english-slug>.md`，全小写英文与连字符，如 `0015-agent-context-layering.md`。
- 编号规则：
  - 4 位零填充递增，取当前目录最大编号 `+1`（可用 `scripts/check-adr --next` 获取）。
  - **禁止复用已删除或已废弃的编号**，允许出现历史跳号，绝不允许重号。
  - 索引或说明文件命名为 `README.md`，不占编号。

## 4. 头部元信息与状态机

标题紧跟元信息列表（前 15 行内）：

```markdown
# ADR-0012：接口鉴权从手工 Cookie 改为短期令牌

- 状态：Accepted
- 日期：2026-08-20
- 修订：[ADR-0004](0004-anonymous-api-with-cookie-fallback.md) 第二条、第四条
```

推荐状态值：

| 状态 | 含义 | 使用场景 |
| --- | --- | --- |
| `Proposed` | 提议中，尚未拍板 | 需先审阅再开工的高风险决策 |
| `Accepted` | 已采纳并生效 | 常规生效决策；若尚未开工可注 `Accepted（待开工）` |
| `Deprecated` | 已停用，无替代决定 | 对应功能或通道整体下线 |
| `Superseded by ADR-XXXX` | 已被新决定整体取代 | 必须给出具体新编号与相对链接 |

若新 ADR 只修改旧 ADR 的部分条款，旧 ADR 状态保持 `Accepted`，在括号内补注指针，例如：
`- 状态：Accepted（第二、四条由 [ADR-0012](0012-token-auth.md) 修订）`。

## 5. 两种正文模板

### 模板 A：标准决策型

```markdown
# ADR-NNNN：结论式标题

- 状态：Accepted
- 日期：YYYY-MM-DD
- 关系：[ADR-XXXX](XXXX-slug.md)

## 背景

描述当前问题、硬约束与实测事实，不写空泛动机。

## 决定

**一、核心结论一。** 具体边界、归属与行为规则。

**二、核心结论二。** 涉及的数据结构、接口或模块去处。

## 放弃方案

- **方案 A**：简述做法与否决原因。
- **方案 B**：简述做法与否决原因。

## 后果

- 正面收益与新增约束；
- 受影响的文档、模块或旧 ADR 条款。

## 验收

（可选）记录实际跑过的命令、线上或真机观察结果；未实测时不虚构结论。
```

### 模板 B：重构拆步型（替代过程留痕文档）

适用于跨多次提交、多模块的结构性迁移：

```markdown
# ADR-NNNN：将命令式共享控件逐块迁为声明式组件

- 状态：Accepted（待开工；逐块交付，每块一个可回滚提交）
- 日期：YYYY-MM-DD
- 关系：[ADR-XXXX](XXXX-slug.md)

## 背景

列出当前遗留模块与实测规模（文件数、行数、高频引用点），标明统计日期。

## 决定

### 1. 分类判据与目标归属

用表格写清哪些保留、哪些迁移、各自落到哪里。

### 2. 拆块顺序

按「零行为变化 → 行为可变」列出可独立回滚的批次（1、2、3……）。

### 3. 每块验收门槛

写清每交付一块必须通过的构建、测试或真机验证命令。

### 4. 收尾判据

给出可机械验证的完成条件（例如旧目录消失、遗留引用数归零）。

## 后果

说明调用方唯一需要改写的形态与过渡期约束。

## 不做什么

明确列出本次有意排除的事项，防止中途范围蔓延。
```

## 6. 与其他文档的职责分界

| 文档位置 | 回答的问题 | 时间维度 |
| --- | --- | --- |
| `AGENTS.md` | 每次改代码前必须成立的安全边界与入口索引 | 始终成立的硬约束 |
| `docs/*.md` / `docs/contracts/` | 系统现在怎么用、接口与领域必须满足什么契约 | **只写最终态** |
| `docs/adr/NNNN-*.md` | 为什么定成这样、否决了什么、旧决定如何被修订 | **追加式决策历史** |
| Git commit / PR / Issue | 某一次改动具体做了什么、测了什么 | 单次变更记录 |
| 会话 / 仓库外目录 | 临时排查日志、个人待办、未成型的草稿 | 一次性临时态 |

同一事实只维护一处：ADR 引用契约或代码路径，不复制整段实现代码；常态文档引用 `ADR-NNNN` 解释来历，不把旧方案的历史演变长篇塞进使用手册。

## 7. 控制体积与信号密度

- 目标篇幅：**2–6 KB（约 40–150 行）**。
- 超过 **15 KB 或 250 行** 时，优先检查是否把过程日志、完整 API 表或逐文件清单塞进了 ADR；能下沉到代码、测试或专门参考文档的立刻拆出去。
- 禁止把 ADR 当成「每日进度更新表」反复追加当日进展；进度靠 Git 提交、分支和收尾判据自然反映。
